# 分布式配置 + 层级合并的引用目录解析

当项目位于 `~/codes/infloww/service-creator` 时,需要引用 `infloww-core` 等同组兄弟目录;我们决定采用**分布式配置**(每个文件夹放一个 `.reference-dirs.json`,声明本文件夹下项目可引用的目录),配合**层级合并**(从 cwd 向上逐级收集配置,并集+去重,父级在前子级在后)和**相对配置文件夹的路径解析**,而不是集中式映射表或绝对路径。

- **Status**: accepted
- **Considered Options**:
  - 集中式映射表(一个文件管所有文件夹):新增文件夹要改全局文件,移动文件夹要改映射;否决
  - 就近优先/覆盖语义:子级声明覆盖父级,语义复杂且易踩坑;否决,采用纯并集+去重
  - 绝对路径:整个目录树移动后全部失效;否决,采用相对配置文件夹 + 支持 `~`/绝对路径
- **Consequences**: 引用目录是叶子目标,不递归展开,避免循环引用;无配置时静默输出空列表,不打扰正常流程
